# 01 - The 20-instrument roster: 14 new voices, manifest, placeholder artwork

**What to build:** The launch kit grows from 6 to 20 instruments - pure kit
data, no engine code. `public/kits/launch/kit.json` gains the 14 new entries
(spec §2: Clap, Shaker, Cowbell, Woodblock, Triangle, Cymbal, Bass, Bell,
Chime, Pluck, Boing, Pop, Zap, Drip), keeping the classic six **first** in
manifest order (defaults and sample clips key off those positions). Roles:
the new drums `perc` (Clap and Shaker could argue for `snare`/`hat` but stay
`perc` - V1 ignores roles), the notes and silly group `melodic`.

Sounds are synthesized by extending
`apps/boop/scripts/generatePlaceholderSamples.mjs` in its own idiom, with new
building blocks where needed (vibrato for Boing, staggered noise bursts for
Clap). Per-voice character notes are in spec §2. Budget rules are unchanged:
peak 0.5 per voice, < 400 ms per file. The **Cymbal takes the full 400 ms as
a noise tail** - spec §10.3: noise tails add incoherently so it should pass
the 200 bpm retrigger rule; if the real test disagrees, trim the tail, never
touch `MAX_BPM`.

Artwork: game-icons.net CC BY 3.0 placeholders, per-icon authorship verified
against the upstream `game-icons/icons` source tree and recorded in
`public/kits/launch/ATTRIBUTION.txt`, exactly as ticket 18 did. Update the
sounds section of ATTRIBUTION with the 14 new voice descriptions too.

Spec: §2 (roster), §3 (sounds and artwork), §10.3 (cymbal).

**Blocked by:** None - can start immediately.

**Status:** done

- [x] `kit.json` lists 20 instruments, classic six first, all parsing through `parseKitManifest`
- [x] 14 new wavs generated by the committed generator script; every voice < 400 ms, peak ≤ 0.5
- [x] `kitLevels.test.ts` extended to all 20 ids: duration, peak, and the 200 bpm retrigger-buildup rule (< 1.4x) all green - including the 400 ms cymbal
- [x] The dense-hit budget test is rethought for 20 instruments (the old six-row sum is no longer the worst case - see ticket 08 for the layered-union budget; this ticket just keeps the test meaningful, not silently weakened)
- [x] 14 new SVGs render via the existing mask-image tinting; ATTRIBUTION.txt carries verified per-icon authorship and the new voice descriptions
- [ ] The app still boots and plays with the 20-instrument kit loaded (existing suites green) - **not satisfiable by this ticket alone**, see the comment below: the app boots and plays, but 11 `.iwft` geometry tests assert a 6-row grid and today's row derivation is the kit, so they need tickets 02/03.

## Comments

**2026-09-02** - Built on an isolated worktree branch (ticket 02 was in flight
in parallel), verified with `pnpm lint`, `pnpm typecheck` (both green
repo-wide), `pnpm --filter boop exec vitest run` (370 green) and the boop
`.iwft` suite (220 green, 11 red - see below).

What landed:

- **The generator** (`apps/boop/scripts/generatePlaceholderSamples.mjs`) gains
  the 14 voices plus four building blocks: `vibrato` (Boing), `delayed`
  (Clap's and Shaker's staggered bursts), `softAttack` (Chime), and an
  optional `seed` on `noise` so stacked bursts can decorrelate. A per-voice
  `levels` map lets a voice sit under the 0.5 peak - only the Shaker uses it
  (0.55), for the spec's "quieter than the hat".
- **Deliberate change of default:** a bare run now rebuilds only the 14 new
  voices, not all 20. The six wavs on disk came from ticket 18's generator,
  which was never committed, so the script's six definitions (ticket 12's) no
  longer reproduce them - a blanket run would have quietly regressed shipped
  audio. Naming a voice on the command line still rebuilds it. Recorded in the
  script header and in ATTRIBUTION.txt.
- **`kit.json` 6 -> 20**, classic six first, then Drums / Notes / Silly in spec
  §2 order; new drums `perc`, notes and silly `melodic`.
- **Artwork:** 14 game-icons.net CC BY 3.0 SVGs, per-icon authorship verified
  by reading the upstream `game-icons/icons` git tree (each author owns a
  top-level directory, so the path *is* the attribution) and recorded in
  ATTRIBUTION.txt, which also gains the 14 voice descriptions. Upstream files
  wrap each glyph in a full-canvas background rect; that rect is stripped (a
  mask-image tint would otherwise paint a solid tile), leaving the same
  single-glyph shape the handoff's six already had. Also corrected the six
  existing attribution paths, which carried a non-existent `icons/` prefix.
- **`kitLevels.test.ts`** now takes its ids from the manifest (kits are pure
  data) and asserts, for all 20: duration < 400 ms, per-voice peak <= 0.5, and
  retrigger buildup < 1.4x over 8 hits at 75 ms.

Measurements and deviations:

- **The cymbal keeps its 390 ms tail, but spec §10.3's arithmetic was wrong.**
  A slow tail (decays 6.5 + 3.0) measured **1.74x**, not ~1.16x: noise does
  add incoherently, but eight overlapping hits still sum in *power*, and the
  peak of summed noise sits above that. What the rule constrains is the decay,
  not the length. Decays 14 + 9 keep the tail audible (within 1% of peak) to
  ~368 ms of the 390 ms file and measure **1.20x**. `MAX_BPM` untouched.
- **Bass and Boing were also retuned on measurement**, not taste: bass decay
  14 measured 1.40x (a 90 Hz tail overlaps nearly in phase at 75 ms) and boing
  decay 12 measured 1.50x (the wobble does not decorrelate one hit from the
  next - every hit is the same waveform). Now 1.24x and 1.23x.
- **Dense-hit budget test, rethought not weakened.** The classic-six sum is
  kept exactly as it was (measures 1.813 against its 1.83 pin - still the
  figure `ToneAudioDriver` was tuned against), and a second test pins the
  whole-roster union at **<= 3.1** (measured **2.970**; the per-voice peaks
  would give 8.947 if they all peaked in phase, which they do not). That pin
  is an anti-regression floor, not the budget: the comment says in as many
  words that **ticket 08** owns re-measuring the union (including one
  instrument sounding from two layered clips), stating the final budget and
  retuning `MASTER_GAIN`, and that raising the number is that ticket's call.

**The one unticked box, and why.** Growing the kit *does* change the live app
today, which the spec did not anticipate: `blankPattern` (HomePage),
`samplePattern` (sampleClips) and `storedToPattern` (saveFormat) all map
`kit.instruments` to rows, so with 20 instruments the grid renders 20 rows.
Verified in the real harness with a throwaway probe (since removed): the CT
server serves the real `kit.json`, the app boots, loads all 20, and renders
320 cells with 20 rail icons - so the artwork and the kit load fine, and the
engine plays. The consequence is 11 red `.iwft` tests, every one of them a
6-row geometry assertion:

- `playBarPinned.iwft.tsx` x5 (the 6 x 16 checks at laptop/tablet/phone plus
  the playhead-column ones that follow them)
- `songBarIsHome.iwft.tsx` x3 (phone/tablet/laptop "still 6 x 16" in the card)
- `laptopColumnFits.iwft.tsx` x2, and `HomePagePom.verifyGridIsSixBySixteen`
  is the shared assertion behind most of them

Those are tickets 02 and 03 by their own text - 02 makes the engine's default
pattern "the roster's first six" and renders from pattern rows, 03 makes
stored rows authoritative and keeps `sampleClips` on the first six - plus
02's ADR 0027 amendment, which is what re-words "6 x 16, always". I did not
touch the engine types, the save format, or song/grid code, and I did not
adjust those tests to match a 20-row grid: doing either would have taken
another ticket's decision. Nothing outside the kit data path changed.

Notes for downstream tickets:

- **Ticket 05 (picker groups):** roles cannot express the spec's groups. Drums
  are `kick`/`snare`/`hat`/`perc`, but **Notes and Silly are both `melodic`**,
  so role alone cannot separate them. Manifest order is classic six first,
  then drums, then notes, then silly - contiguous for the new 14, but Marimba
  and Boop (Notes) sit inside the leading six. So the picker needs either its
  own group list or a new manifest field (which the v1 parser would ignore, so
  exposing it means touching `parseKitManifest`).
- **Ticket 07 (thumbnails/loop map):** 20 rows is now reachable in a clip.
- **Ticket 08 (gain budget):** start from 2.970 raw for a 20-voice union
  (1.813 for the six). Through today's `MASTER_GAIN` 0.6 that is ~1.78 into a
  Limiter(-1), so the limiter would be doing real work on a dense 20-row hit.
  The cymbal is the hottest new voice by far (0.48 peak across 390 ms).
- **Ticket 28 (real artwork):** the placeholders read acceptably except
  Triangle, which is `pool-triangle` (a billiards rack) - the icon set has no
  triangle instrument. Cowbell is a cow, Cymbal a metal disc, Clap a
  high-five.
