# Design brief

Type: task
Status: resolved
Blocked by: 07

## Question

Draft a design brief the user can paste into a design tool (e.g. Claude
design): screens and interactions from the spec, the chosen visual direction,
mobile-first layout notes for tablet/laptop, tone (playful, kid-friendly 6+).
The spec defines *what* exists; this brief describes it for visual design.

## Answer

**Design brief delivered at [`design-brief.md`](../design-brief.md)** (added
to the tracker's gitignore carve-out alongside `spec.md`). It translates the
spec into design language: product-in-a-paragraph, tone (playful 6+, toy not
tool, words sparingly, no flashing), the single main screen broken into four
regions (grid hero, transport+tempo, starter-groove preset row, quiet
save/share/help corners), the six launch-kit instruments as a character/
artwork set, the fixed interactions to design around (latched drag-paint,
audible edits, playhead), layout targets with the small-phone 6×16 treatment
called out as the one hard problem left to the designer, bounded motion
guidance, a numbered deliverables list, and prior-art reference points from
the survey. Open visual questions from the spec's handoff section are framed
as designer decisions, not pre-answered.
